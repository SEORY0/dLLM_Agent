# 팀원 공유용 카톡 텍스트 (초안, 2026-09-30)

바로 복사해서 붙여넣을 수 있도록 메시지 2개로 나눠뒀습니다.

---

## 메시지 1

그동안 진행한 dLLM(확산 언어모델) 기반 퍼징 하네스 자동 생성 실험 정리해서 공유드려요.

목표는, OpenEXR 퍼징 하네스를 Dream-Coder라는 확산 언어모델로 자동 생성할 때 모델이 생성 도중 보이는 "확신도(confidence)" 신호로 어디를 고쳐야 할지 짚어주면, 무작위로 고치는 것보다 나은 결과가 나오는지 확인하는 거였어요.

전체 흐름은 이렇게 진행했어요.
1. 먼저 작은 시뮬레이션으로 아이디어 자체가 말이 되는지 확인
2. 실제 GPU에서 Dream-Coder를 돌려서 하네스 생성 → 컴파일 → 퍼징까지 되는 파이프라인 구축
3. "확신도가 컴파일 에러 위치를 잘 짚는가"를 독립 샘플 224개로 검정
4. "확신도 기반으로 고치면 결과(커버리지)가 더 좋아지는가"를 스모크 테스트 → 기준선이 안정적인지 감사(두 차례) → 하네스를 생성하는 방식 자체를 두 번 바꿔가며 소규모 비교, 순서로 검정

## 메시지 2

결과는 세 가지로 나눠서 봐야 해요.

1) **된다**: dLLM으로 실제 하네스를 생성해서 컴파일하고 퍼징까지 돌리는 건 확실히 가능하다는 걸 여러 차례 GPU에서 확인했어요.
2) **아직 못 찾음**: "확신도로 고칠 위치를 고르면 무작위보다 낫다"는 증거는 이번 조건들에서는 못 찾았어요. 마지막 비교 실험에서는 확신도 쪽과 무작위 쪽 승패가 거의 정확히 반반이었어요. 효과가 없다고 단정하는 건 아니고, 표본이 작아서 "이번엔 우위를 못 찾았다" 정도로만 말할 수 있어요.
3) **아직 미판정**: dLLM이 기존 자기회귀(AR) 모델보다 퍼징을 잘하는지, 비용이 더 싼지는 이번 실험 범위 밖이라 여전히 답을 못 낸 상태예요.

그래서 확신도 기반 실험 라인은 여기서 마무리하려고 해요(dLLM 퍼징 프로젝트 전체를 접는 게 아니라 이 한 갈래만요). 코드·실험 스크립트·원본 결과는 전부 남겨뒀고, 브랜치는 테스트 통과와 정리까지 확인해서 머지 가능한 상태로 만들어뒀어요.
